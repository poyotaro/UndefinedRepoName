# ランキングの送信の仕様（プロトコル v3、2026-10-14）

v2（docs/protocol.md）からの変更の理由：
- ID の重なり：v2 の ID は各端末の乱数（uid、64bit）の下 30bit で、来訪者 1 万人で約 5% の確率で 2 人が同じ ID になる。
- 名前の乗っ取り：v2 は誰でも他人の ID で名前を送れる。
- 送信の回数：v2 の試合の記録は 7 語（約 35 秒）。

v3 は ID をサーバーが配る（登録簿）。同じ uid には必ず同じ ID を返すので、重ならず、照合も外れない。ID は 1 から順に配るので短く、記録は 4 語になる。

## 経路と URL
- URL は `/3/0`〜`/3/4095`（v2 と同じ 11bit ずつ。n >= 2048 がフレームの始まり）。ワールドの URL の束を作り直す。
- **文字列の経路 = 登録と名前**（返事を読むため）。**画像の経路 = 試合の記録**（返事は要らない）。2 つの経路は並行して送れる（それぞれ 5 秒に 1 回）。
- 文字列の経路のフレームの始まりの 1bit が種類：0 登録・1 名前。

## ID の長さの符号（2bit）
| 符号 | ID の bit 数 | 範囲 |
|---|---|---|
| 0 | 10 | 0〜1,023 |
| 1 | 16 | 〜65,535 |
| 2 | 22 | 〜約 419 万 |
| 3 | 30 | 〜約 10.7 億 |
ID 0 は「無し・不明」（相手がいない・分からない）。

## 登録（文字列の経路、種類 0、72bit = 7 語）
| bit | 中身 |
|---|---|
| 1 | 種類 0 |
| 64 | uid（PlayerData の PoyoWorld.uid、16 進 16 桁をそのまま 4bit ずつ） |
| 7 | 検査値（前の 65bit に v2 と同じ check7） |

- 最後の語の読み込みへの返事が `id\t<ID>`（それ以外の語は `ok`、検査値の不一致は `bad`）。
- サーバーは uid が登録簿にあればその ID、なければ新しい ID を返す。同じ uid は何度登録しても同じ ID。
- ワールドは返ってきた ID を PlayerData（`PoyoWorld.rankId`）に保存する。保存済みなら登録しない。
- 返事が読めなかった・`bad` の時は 30 秒〜2 分の乱数の後にやり直す（同じ IP の 2 人が同時に送ると混ざって `bad` になる）。
- 1 つの IP（ハッシュ）から 1 日に新しく作れる ID は 20 まで（作りすぎの防止。既存の uid の再登録は数えない）。

## 名前（文字列の経路、種類 1）
| bit | 中身 |
|---|---|
| 1 | 種類 1 |
| 5 | 文字数（1〜31） |
| 2 | ID の長さの符号 |
| 10〜30 | ID |
| 24 | 合言葉：uid の先頭 6 桁（24bit）。uid はサーバー以外に出ないので、他人の名前は変えられない |
| 16 × 文字数 | 名前（UTF-16） |
| 7 | 検査値（前の全部に check7） |

- サーバーは ID の uid の先頭 24bit と合言葉が合う時だけ名前を保存する。返事は `ok`（合わない・検査値の不一致は `bad`。やり直さない）。
- 10 文字・ID 1,000 未満で 208bit = 19 語（v2 と同じ）。送るのは v2 と同じく、自分の順位のファイルに名前が無いか違う時だけ。

## 試合の記録（画像の経路、ID 1,000 未満の 2 人で 41bit = 4 語）
| bit | 中身 |
|---|---|
| 2 | 自分の ID の長さの符号 |
| 2 | 相手の ID の長さの符号 |
| 10〜30 | 自分の ID |
| 10〜30 | 相手の ID（1 対 1 でない・不明は 0） |
| 4 | 種目 × 2 + ランク戦 |
| 2 | 結果（0 負け・1 勝ち・2 引き分け） |
| 4 | 試合番号の下 4bit |
| 7 | 検査値 |

- フレームの長さは最初の語の 4bit（長さの符号 2 つ）で決まる。ID 6.5 万未満で 5 語、約 419 万未満で 6 語。
- 自分の ID がまだ無い（登録中）うちに試合が終わったら、記録を覚えておき、ID が届いてから送る。相手の ID が分からなければ v2 と同じくランク戦にしない。

## 登録簿（Durable Object の SQLite、消さない）
`players(id INTEGER PRIMARY KEY AUTOINCREMENT, uid TEXT UNIQUE, rid30 INTEGER, ts INTEGER)`
- AUTOINCREMENT なので番号は振り直さない（v2 の記録の表で起きた問題を避ける）。
- rid30 = uid の下 30bit（v2 の ID）。v2 からの移行と、古いワールドの v2 の送信の読み替えに使う。

## v2 からの移行
- 今いる 3 人の v2 の ID に新しい ID を先に割り当てる（uid は空のまま、rid30 だけ入れる）：
  1 = 410606822（ぽよたろう）、2 = 89809756（ミネラルむぎ茶）、3 = 237702707（«つん»）。
- その人が v3 で登録すると、uid の下 30bit が rid30 と同じ空きの行を自分の行にする（成績を引き継ぐ）。
- 集計の state/ と docs/ の ID は、移行の時に 1 回だけ新しい ID に書き換える。
- 古いワールド（v2）の送信は当分受け取る。記録の rid30 を登録簿で読み替え、無ければ空きの行を作って ID を割り当てる（後で v3 で登録すると同じ行になる）。v2 の名前も同じく読み替える。
- 古いワールドの板は自分の ID（v2）で自分の行を探すので、移行の後は「自分の順位」の帯が出ない（上位の一覧は出る）。ワールドを v3 に更新するまでの間だけ。

## 集計の起動を減らす
- Worker の Cron は Durable Object に「前回の起動の後に新しい記録・名前が来たか」を聞き、来ていなければ起動しない。
- 板は自分の順位のファイルを、ranking2.txt の時刻が変わった時と、自分の試合が終わった後の最初の読み込みの時だけ読み直す。

## 変わらないもの
- 集計（2 人の記録の突き合わせ・重み・Elo・書き出しの形式）は v2 と同じ。ID が新しい番号になるだけ。
- 送り元の IP は保存しない（塩つきハッシュの先頭 8 桁だけ）。
