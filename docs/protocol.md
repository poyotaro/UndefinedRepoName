# ランキングの送信と集計の仕様（プロトコル v2、2026-10-12）

v1（W5）からの変更の理由：Cloudflare の無料枠の節約。v1 は 12bit ごとに D1 へ書き、観客の端末も全員分を送り、集計で表全体を何度も読んでいたため、1 日の来訪者 200 人ほどで無料枠を超える試算だった。v2 は来訪者 7,000 人ほどまで無料枠に収まる試算（許可オン 90%・1 人 1 日 2 試合）。

## 全体
1. ワールド（Udon）は読み込みしかできないので、用意した 4096 本の URL `/2/0`〜`/2/4095` の「どれを読むか」で 11bit ずつ送る。
   - n >= 2048：フレームの始まり（中身は n - 2048）。n < 2048：続き。
   - 文字列の経路 = 試合の記録、画像の経路 = 名前。各経路は前の読み込みが終わってから次を送る（VRChat の制限で 5 秒に 1 回）。
   - 許可（Allow Untrusted URLs）が無い端末では読み込みが失敗するだけ。
2. Worker は断片を 1 つの Durable Object（Assembler）に渡す。Assembler はメモリで組み立て、できあがった記録だけを自分の SQLite に 1 行保存する。
   - 送り元の IP は保存しない。秘密の塩（SALT）つきハッシュの先頭 8 桁だけ（2 人の記録が別の場所から来たかを見る）。
   - 同じ IP から 2 人分の断片が混ざると検査値で捨てる。
3. GitHub Actions（tools/update.mjs）が、毎時 0・15・30・45 分に Worker の Cron Trigger から workflow_dispatch で起動されて（2026-10-14。GitHub の schedule は 5〜25 分遅れるので毎時 7 分の予備だけ） `GET /delta.txt?key=<EXPORT_KEY>&since=<記録>,<名前>` で前回より後の記録だけを読み、
   組み合わせ・スタッツ・レーティング・順位を計算して、state/（集計の状態）と docs/（Pages）を更新する。変化がなければコミットしない。
4. ワールドの板は Pages の `ranking2.txt` と自分の `me/NN.txt`（NN = ID % 64）を読む。読むのは入って 10 秒後と、15 分の区切りの 5 分後（afterSlot、時刻は Networking.GetNetworkDateTime）。右上に次に読むまでの残り時間を出す。

## 試合の記録（77bit = 7 語、文字列の経路）
試合が終わった時、参加者本人の端末が自分の分だけを送る（観客は送らない。1 人プレイ・ファウルなしの練習・無効試合は送らない）。

| ビット | 中身 |
|---|---|
| 30 | 自分の ID（PlayerData の uid から） |
| 30 | 相手の ID（1 対 1 の時。ダブルスや不明は 0） |
| 4 | 種目 × 2 + ランク戦（種目 0 9 ボール・1 10 ボール・2 8 ボール・3 スヌーカー・4 ピラミッド・5 3 クッション・6 その他） |
| 2 | 結果（0 負け・1 勝ち・2 引き分け） |
| 4 | 試合番号の下 4bit（同じ 2 人の続けての試合を見分ける） |
| 7 | 検査値：前の 70bit を 10bit ずつ切った c_i の Σ (i+1)·c_i mod 127 |

## 名前（画像の経路）
文字数 5bit（1〜31）・ID 30bit・各文字 16bit（UTF-16）・検査値 7bit（ID と文字の部分に対して同じ計算、最後の切れ端は右を 0 で埋める）。
送るのは、自分の順位のファイルに自分の名前（P の行）が無いか違う時だけ（板が判定して送信部に知らせる）。順位のファイルにまだ何も無い人は、自分の記録を送った後に送る。

## 集計（tools/update.mjs）
- 2 人の記録（自分・相手・試合番号の下 4bit が対応、時刻の差 3 時間以内）がそろったら 1 試合。結果・種目・ランク戦が食い違えば数えない。
- 相手の記録が 10 分待っても来なければ、1 人分の記録で数える（相手のスタッツも逆の結果で数える。レーティングの動きは半分）。
- 遅れて届いた相手の記録は、数え済みの試合（6 時間覚えておく）なら捨てる。
- スタッツ：（ID・種目）ごとの試合数・勝利数。
- レーティング（ランク戦・1 対 1・種目 0〜5）：Elo（初期 1500、K = 32）。同じ 2 人の 24 時間以内のランク戦の数 n で K × 1/(1+0.5n)。2 人の記録が同じ場所（同じ IP のハッシュ）から、または 1 人分だけなら K を半分。
- 記録は集計が読んでから 24 時間で消す。ただし各表のいちばん新しい行は残す（seq は AUTOINCREMENT ではないので、全部消すと 1 から振り直され since 以下になる。2026-10-14 に 1 試合が読まれなかった）。集計は読み済みの最後の時刻（meta.tsv の recTs・nameTs）以前の行を数えないので、since を 0 に戻しても二重に数えない。
- state/：ratings.tsv・stats.tsv・names.tsv・pending.tsv（相手待ち）・done.tsv（数え済み）・recent.tsv（連戦）・meta.tsv（どこまで読んだか）。

## 書き出し
docs/ranking2.txt（中身が変わった時だけ書く）：
```
v2	<UNIX 秒>
N	<種目 0-5>	<順位のある人数>
R	<種目>	<順位>	<ID>	<レーティング>	<試合数>	<名前>      … 各種目上位 20
S	<種類>	<順位>	<ID>	<値>	<名前>                    … 種類 0 試合数・1 勝利数・2 勝率（‰、20 試合以上）、上位 10
```
docs/me/NN.txt（NN = ID % 64、2 桁）：その ID の人の行だけ。
```
v2
M	<ID>	<種目>	<順位>	<人数>	<レーティング>	<試合数>
T	<ID>	<通算試合数>	<通算勝利数>	<試合数の順位>	<勝利数の順位>	<人数>
P	<ID>	<名前>
```

## 秘密
- Worker：SALT（IP のハッシュの塩）、EXPORT_KEY（/delta.txt の鍵）、GH_DISPATCH_TOKEN（集計の起動。UndefinedRepoName の Actions: Read and write だけの Fine-grained トークン。期限が切れたら作り直して上書き）。`wrangler secret put` で設定。
- GitHub：RANKING_KEY（= EXPORT_KEY）。Actions が使う。

## 不正への考え方
送信は誰でも作れるので完全には防げない。2 人の記録の突き合わせ、1 人分・同じ場所からの記録は重みを半分、同じ相手との連戦は重みを減らす、で影響を小さくする。

## 旧形式
v1（`/0`〜`/4095`、export.txt・bundle.txt・D1）は廃止。古いワールドからの v1 の送信は受け取って捨てる。docs/ranking.txt（v1 の書き出し）は更新しない。
