# ランキングの送信と書き出しの仕様（W5、2026-10-12）

## 全体
- ワールド（Udon）は読み込みしかできない。`https://poyo-billiards-ranking.rankingserver.workers.dev/<n>`（n = 0〜4095）の 4096 本の URL を
  ワールドに入れておき、どれを読むかで 12bit を送る。経路は 2 本：文字列の読み込み（VRCStringDownloader）と画像の読み込み（VRCImageDownloader）。
- どちらの経路も 5 秒に 1 回まで。1 本の経路では前の読み込みが終わってから次を出す（順番を保つ）。サーバーは送り元の IP と経路（Accept が image/* なら画像）ごとに組み立てる。
- workers.dev は信頼ドメインではないので、送るのは「Allow Untrusted URLs」を許可した人の端末だけ（許可していなければ読み込みが失敗するだけ）。
- 集計は Worker の `/export.txt`。公開リポジトリの GitHub Actions が 15 分ごとに `docs/ranking.txt` に写し、GitHub Pages
  （`https://poyotaro.github.io/UndefinedRepoName/ranking.txt`、信頼ドメイン）でワールドが読む。

## 12bit の断片
`n = 見出し × 1024 + 中身（10bit）`
| 見出し | 意味 |
|---|---|
| 3 | 試合の報告の半分の始まり（中身は最初の 10bit） |
| 2 | 続き（直前のフレームに 10bit を足す） |
| 1 | 名前の始まり（中身は文字数 1〜32） |
| 0 | 使わない |

## 試合の報告（1 人分）
- 文字列の経路で半分 A、画像の経路で半分 B を、それぞれ 3 断片（30bit、大きい桁から）で送る。0・5・10 秒で 6 断片、約 10 秒で終わる。
- A：試合番号 24bit（台の GameState.matchId）・結果 2bit（0 負け・1 勝ち・2 引き分け）・種目 3bit（PlayerProgress.Kind*）・ランク戦 1bit
- B：プレイヤーのランキング ID 30bit（PlayerData の uid から作る。0 は無効）
- サーバーは同じ IP の A と B を古い順に組む（60 秒以内）。報告は（試合番号・ID）で 1 つ（最初のもの）。
- 送る順：自分の分を先に、続けて同じ試合の相手の分（相手の ID は PlayerObject の同期で知る）。相手が許可していなくても載る。

## 名前
- 文字列の経路で、見出し 1（文字数）の後に、ID 30bit・各文字 16bit（UTF-16）を 10bit ずつの断片で。手が空いている時に送る（急がない）。

## 集計
- スタッツ：報告ごとに（ID・種目）の試合数・勝利数。
- レーティング（ランク戦・1 対 1）：同じ試合の 2 人の報告がそろい、結果が食い違わなければ Elo（初期 1500、K = 32）。
  - 同じ 2 人の 24 時間以内のランク戦の数 n で K × 1/(1+0.5n)。
  - 2 か所（2 つの IP）から届けばすぐ反映。1 か所だけなら 2 分後の定期処理（30 分ごと）で K を半分にして反映。
  - ファミリー：0 プール（9・10・8 ボール）・1 スヌーカー・2 ピラミッド・3 キャロム。

## 書き出し（タブ区切りの行）
```
v1	<UNIX 秒>
F	<ファミリー>	<順位>	<ID>	<レーティング>	<試合数>	<名前>      … 各ファミリー上位 50
S	<種類>	<順位>	<ID>	<値>	<名前>                          … 種類 0 試合数・1 勝利数・2 勝率（‰、20 試合以上）、上位 50
```

## 不正への考え方
- 「疑似」レーティング。送り方はワールドから分かる前提。値の範囲の確認、2 人の結果の一致、同じ IP だけの報告の重みを下げる、連戦の減衰で抑える。
- サーバーには送り元の IP が届く（ワールド内で告知する）。
